# Plumbing homepage recreation

Plain HTML and Tailwind CSS, with vanilla JavaScript for menus, reviews, local search, and demo form feedback. No frontend framework or runtime dependencies.

## Preview

Run `npm start` and visit **http://localhost:3001**, or open `index.html` directly. The full homepage is implemented, from the utility bar through the footer and mobile call button. The original Stage 1 board is preserved at `foundation.html`.

Both contact forms and the newsletter use native required-field/email validation and show explicit demo confirmations; they send no data. Phone links use the configured number. Navigation for sections on the homepage stays on this page; links to excluded service, article, legal, and suburb pages retain their original website destinations. Location lookup filters the five featured suburbs; homepage search also finds all 216 suburbs and activates the matching region tab. These are local preview behaviors, not copies of the original backend.

## Rebranding

- **`assets/site-config.js`**: company name, phone display/call destination, email, address, opening hours, and image overrides. No rebuild needed for these settings; refresh the page.
- **`styles/theme.css`**: all global colors, heading/body/accent fonts, font files, and breakpoints. Rebuild after editing.
- **`index.html`**: static homepage content, section structure, and link destinations.
- **`assets/site.js`**: menus, reviews, region tabs, search, gallery controls, demo forms, and applying business settings.
- **`assets/images/`** and **`assets/fonts/`**: local assets; no external asset CDN is required by the rendered page.

For image overrides, add the existing filename as a key in `SITE_CONFIG.images` and use your replacement file path as the value. Hero and process backgrounds also use these settings. Keep suitable aspect ratios for the closest visual match. Service descriptions, customer reviews, social profile destinations, and other business-specific copy are static HTML and should be edited during rebranding.

## Styles

- Edit **`styles/theme.css`** to change all colors and font families.
- Use semantic Tailwind classes such as `bg-brand`, `text-ink`, `font-heading`, and `font-accent`.
- Run `npm run build` after changing HTML classes or the theme.
- Run `npm run watch` while editing to rebuild automatically.
- Do not edit `assets/site.css`; it is generated by Tailwind.
- Font URLs in the source stylesheet are relative to the compiled file in `assets/`.

## Reference assets

Images are in `assets/images/`, fonts in `assets/fonts/`. `reference/assets.json` maps every collected source URL to its local path and records download failures. Reference HTML and CSS are for inspection only and are not loaded by the implementation. Original scripts, forms, and tracking code are not used.

## Review stages

1. Design foundation: source inspection, assets, centralized theme, review board.
2. Header, hero, opening reviews, benefits, quote form.
3. Services, reasons, financing, call banner, company introduction, guarantees.
4. Testimonials, projects, process, service areas, blog cards.
5. Final contact area and footer.
6. Responsive, interaction, accessibility, and visual verification.

Stages 1–3 were reviewed. The user then authorized completing all remaining stages together. All homepage sections are implemented. Service cards open on hover with a mouse or by tapping/clicking their summaries. They support keyboard activation, Escape, and explicit close controls. Mobile service cards scroll horizontally. Region tabs support Up/Down, Home, and End. Reviews and gallery have pause controls and respect reduced-motion preferences.

## Checks

- `npm run build`: compiles local Tailwind CSS 4.3.3.
- `npm run check`: JavaScript syntax plus DOM checks for rebranding, menus, reviews, region tabs, search, demo forms, gallery controls, IDs, anchors, ARIA targets, and asset existence.
- Linkedom is a development-only checker and is not loaded by the website.
- `reference/` contains the original source snapshot, asset provenance, build-time extraction scripts, and verification scripts. The site does not load these files.
- If hosting the site, publish `index.html` and `assets/`; Node, `reference/`, and development dependencies are not needed for the static website.

## Verification limits

Source styles and markup were used to reproduce layouts and responsive breakpoints. The CSS build, syntax checks, and DOM interaction checks pass. No browser is connected to this session, so rendered desktop/mobile layout, browser-native form validation, and pixel matching have not been visually verified. DOM checks do not replace browser testing.
